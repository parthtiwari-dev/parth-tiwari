# DESIGN LOCK — EPHEMERIS

Single source of truth for this project's 2D visual language. Generated by `/design-pass init` on 2026-08-14. Conflicts between design sources are resolved **here, once**. Later passes read this rather than re-deriving.

**Scope note:** this lock governs the *chrome* — overlays, cards, the conversion layer (BookingCta, ContactPanel, ServicesBlock, ProjectIndex), typography, and the plain-mode route. It does not govern the WebGL universe itself; that system already has its own design document at `docs/DESIGN.md` and its own camera/motion rules. Where the two could conflict, `docs/DESIGN.md` wins for anything inside the 3D scene, and this lock wins for anything in the DOM.

## Ground

- **What this is:** A personal portfolio built as a navigable universe, existing to generate leads for paid AI product work at ₹50k–1L per project.
- **Who lands on it, and how they arrive:** A founder or small-business decision-maker, from cold outreach, on a phone, giving it about sixty seconds, mildly skeptical. Secondarily a recruiter, served by the same page.
- **The page's single job:** Answer three questions fast — *is this person real, can they actually build, and what would this cost me in risk* — and put a booking action one tap away at every point in that answer.

## Target

- **Source:** `refs/design-md/warp/DESIGN.md` (primary) + `refs/design-md/vercel/DESIGN.md` (secondary). No `inbox/refero/` captures existed at this pass — `styles.refero.design` is disallowed by its own `robots.txt` for AI agents, so this skill does not fetch it; the user can save captures there for a future pass and they will take precedence over these two.
- **Borrowed structurally, from Warp:** one non-chromatic primary color functioning as *both* default ink and CTA fill, with no separate accent hue; elevation from surface-contrast plus a single hairline ring rather than drop-shadow; a restrained, lightly-tracked-negative display weight instead of a bold one; strict separation where the monospace face touches only the technical/proof layer, never narrative copy.
- **Borrowed structurally, from Vercel:** exactly one decorative system for the entire page, reserved for one place, never miniaturised or repeated elsewhere; section-surface polarity as the primary depth cue marking a shift in register (here: marketing register vs. proof register, rather than light vs. dark mode).
- **Explicitly NOT borrowed:** Warp's literal warm-charcoal hex or off-white primary (EPHEMERIS keeps its own near-black `--bg` and gold `--gold`); Vercel's mesh gradient itself, its pill-shaped CTAs, or its light-mode canvas.

## Divergence

Five structural abstractions taken from the target (no brand-identifying detail):

1. Exactly one non-chromatic "primary" color functions as both default ink and the CTA fill — no separate accent hue exists for buttons.
2. Elevation comes from surface-contrast plus a single hairline ring, never a heavy drop-shadow; where more weight is needed, it is built from two or three stacked near-transparent offsets, not one blurred blob.
3. Display type sits at a light-to-medium weight with negative tracking, not bold — restraint reads as confidence, not absence.
4. A second, monospaced face is reserved exclusively for the technical/verifiable layer and never touches narrative copy, so its mere presence signals "this part is checkable."
5. A single background-polarity shift is the primary depth cue between adjacent registers of content, used once, not scattered across every card.

Mutation operators applied (three, from `references/divergence.md`):

| Operator | What it changed |
|---|---|
| 5 — Constrain harder | No gradient, no atmospheric 2D decoration of any kind is permitted in the chrome. The project already has exactly one decorative system — the WebGL universe — and Vercel's own rule ("reserve the one decorative system for one place") is honoured precisely by refusing to add a second, competing one in 2D. |
| 2 — Displace the signature | Vercel's signature move — one atmospheric decorative system, hero-scale only — is kept as a *rule* but the decorated object is displaced from a mesh gradient onto the constellation itself. The 2D chrome's job becomes staying quiet enough that the universe can be the one loud thing on the page. |
| 6 — Borrow from outside the category (strongest operator) | The signature element for every data-bearing surface (Proof metrics, Services, evidence tables, the project index) is not a SaaS card grid — it is an **observation log**: monospace row index, right-aligned numerals, hairline row dividers, a fixed-width "coordinate" column. This is not decoration borrowed from another website; it is the literal object the site is named for — an ephemeris is a table of computed positions, and the UI for proof now reads like one. |

**Clone check:** would either target's designer recognise their own work here?
**Recorded answer:** "No, but I see the shared logic." A near-black canvas with a single gold ink-and-CTA color, hairline elevation, mono-for-proof-only, and a literal astronomical-logbook table for evidence shares no surface identity with either Warp or Vercel. The underlying logic — one non-chromatic primary doing double duty, restraint over embellishment, exactly one decorative system, monospace as a trust signal — is legible as shared DNA only if you already know to look for it.

## Dials

| Dial | Value | Why |
|---|---|---|
| VARIANCE | 3 | Ground demands fast, confident scanning from a skeptical buyer on a 60-second budget. The chrome stays mostly regular with two deliberate breaks (the hero and the observation-log motif); the universe is where asymmetry already lives, governed separately by `docs/DESIGN.md`. |
| MOTION_INTENSITY | 3 | Trust-critical surfaces — services, the contact form, the booking CTA — must not compete with the spectacle of the 3D scene for a visitor's limited attention. Purposeful entrance and hover only, 150–300ms ease-out. The universe itself runs far higher and is intentionally out of this dial's scope. |
| VISUAL_DENSITY | 4, with an explicit carve-out to 6–7 inside Proof/Architecture panels | The landing/hero/services/CTA layer needs a fast, comfortable skim (this is the "convince me to look further" layer). The evidence panels are the "prove it" layer and are allowed to run denser — that density is itself part of what makes them read as technical and credible. |

If MOTION_INTENSITY were above 5 a `prefers-reduced-motion` fallback would be required here; at 3 the existing project-wide reduced-motion discipline (already strong per `CLAUDE.md`) fully covers it.

## Palette

Named by role, not by hue — mapped onto the project's existing `src/styles/tokens.css` rather than replacing it. This lock does not invent new hex values where a token already exists and is correctly scoped.

| Role | Value | Notes |
|---|---|---|
| canvas | `--bg` (`#010409`) | Unchanged. Already close in spirit to Warp's "not pure black" principle in intent, if not in literal warmth. |
| surface | `--surface-glass` region, recontracted | Currently under-specified — see Rejected findings. Should read as one deliberate lift off canvas, not a blur-heavy glass treatment. |
| ink | `--ice` (`#d8eaf0`) | Unchanged. Already the default text color; keep it that way. |
| ink-muted | `--ice-muted` / `--ice-faint` | Unchanged, but audit contrast per `docs/AUDIT.md` A-series findings before this lock is treated as final. |
| accent (single, doubles as CTA) | `--gold` / `--gold-glow` | **This is the one interactive colour.** It already exists and is already used this way — the discipline this lock adds is refusing to introduce a second accent anywhere in the chrome, including `--teal-active`, `--amber`, and `--utility`, which stay scoped to the 3D node-kind legend only and must never leak into 2D conversion UI. |

## Type

Existing role split (Spectral display / Geist Mono technical / Inter body) is correct and is kept exactly as-is — this is the one part of the current system the audit already called genuinely good.

| Role | Face | Size / clamp | Weight | Tracking | Leading |
|---|---|---|---|---|---|
| display | Spectral | existing `--text-hero` / `--text-2xl` clamps | 300 | slightly negative at largest sizes | tight |
| body | Inter | existing `--text-base`/`--text-sm` | 400 | 0 | comfortable |
| technical / proof | Geist Mono | existing `--text-xs` | 400 | slightly positive, uppercase for labels only | tight |

The change this lock makes is not to the faces or the scale — it is to **enforcement**. `docs/AUDIT.md` already found 41 ad-hoc `clamp()` declarations with no shared ratio and 33 fixed sizes outside the token set. That drift is what this lock exists to stop; see Ranked plan in a future `DESIGN_REVIEW.md`.

## Spacing and rhythm

- Base unit: keep the existing 4px-derived rhythm implied by current spacing usage; do not introduce a second base unit.
- Scale: consolidate around the existing `--text-*` scale's implicit rhythm rather than adding a parallel spacing scale copied from either target brand file.
- Max content width: unchanged from current layout; not a finding.

## Motion budget

- Default duration / easing: 150–300ms, `--ease-out-expo` (already defined in `tokens.css`) for entrances; `--ease-in-out` for state toggles.
- What is allowed to move: hover/focus states on interactive chrome, panel enter/exit transitions, the existing observation-log row reveal (new).
- What must never move: body text reflow, the booking CTA's position (it is a fixed anchor, not an animated one), anything under `prefers-reduced-motion`.

## Signature element

**The observation log.** Every surface in the chrome that presents evidence — the Proof panel's metrics, the new `ServicesBlock`, the `ProjectIndex` rail, and any future testimonial or outcome list — renders as a table with a monospace row index (`01`, `02`, ...), a hairline divider between rows, right-aligned numerals where a value exists, and a fixed-width leading column that reads like a coordinate or timestamp column in a real logbook. No card-grid treatment for data; the observation log is the one, consistent shape data-bearing content takes across the whole chrome.

Concretely: a `.observation-log` component with `role="table"` semantics (or a real `<table>` where the content is genuinely tabular, e.g. Proof metrics), monospace index column at `--text-xs`, `1px solid var(--ice-faint)` row dividers, and no background fill on rows — the hairlines alone carry the structure, per the Warp/Vercel-derived elevation rule.

## Banned

| Banned | Reason |
|---|---|
| A second accent color anywhere in 2D chrome | The single-accent discipline is the whole point of the target; `--teal-active`/`--amber`/`--utility` stay inside the 3D legend only. |
| Drop-shadow as the primary elevation cue on any card or panel | Both target brands carry elevation via surface-contrast + hairline; a heavy blurred drop-shadow reads as a template default, which is exactly what this lock exists to avoid. |
| A gradient or atmospheric 2D decorative layer anywhere outside the WebGL canvas | Constrain-harder mutation; the universe is the one decorative system this project gets. |
| Card-grid layout for any evidence/proof/data surface | The observation log is the signature element specifically *because* it is not a card grid — using a card grid for Services or Proof undoes the divergence work in this lock. |
| Pill-shaped CTAs at marketing scale | Belongs to Vercel specifically; not borrowed. Keep the tighter, more rectangular radius already implied by the existing token set. |
| Bold (700+) display type | Both targets cap their display weight well below 700; the existing Spectral 300 already honours this and should not be pushed heavier for "impact." |

## What is unavailable in this environment, and what that means

No `design-kit` install is reachable on this machine — the `vendor/impeccable` detector scripts (Stage 4) and the `vendor/ui-ux-pro-max` CSV corpus (Stage 3) do not exist here. This lock was produced from **Stage 0 (Ground), Stage 1 (Target), Stage 2 (Dials), and Stage 3.5 (Diverge) only.**

Practically: candidate palettes/font pairs from the statistical corpus were never consulted (not a loss — the skill itself says the average is the enemy of a distinctive site, and Ground plus the two target brand files were sufficient to derive a specific palette). Deterministic anti-pattern detection was **not run**. Any subsequent `/design-pass audit` in this environment must say plainly that its findings are judgment-based, not detector-verified, and should note the gap rather than imply detector coverage that did not happen.
